## 二、Java 业务后端（backend-java/，:8081）

### 2.1 技术要点

- Spring Security + JWT **双 Token**：access 2h / refresh 7d
- `JwtAuthenticationFilter`：**principal 为 userId 字符串**
- MyBatis Plus；主键 `varchar(36)` 存 UUID 字符串（非 PostgreSQL UUID 类型）
- Redis 存邮箱验证码
- 统一响应 `Result`：`{code, message, data, timestamp}`，code=200 成功
- JSON 字段 **camelCase**（DTO 上 `@JsonProperty` 显式声明）；DB 列 snake_case

### 2.2 包结构

```
com.ai.companion/
├── controller/    # Auth / User / Companion / Chat / AI
├── service/ impl/ # 业务实现
├── mapper/ entity/ dto/
├── config/        # SecurityConfig, RedisConfig
├── security/      # JwtAuthenticationFilter, JwtUtil
└── common/        # Result 统一响应
resources/
├── application.yml
└── schema.sql     # 5 张业务表 + 4 个预置伴侣
```

### 2.3 数据表（schema.sql）

| 表 | 说明 |
|----|------|
| `user` | 用户（id varchar(36), email, password, name, avatar） |
| `companion` | 伴侣（含 personality, tags 逗号分隔 String, is_preset, created_by） |
| `conversation` | 对话会话（user_id + companion_id 维度） |
| `message` | 消息（role, content, images TEXT 存 URL 的 JSON 数组） |
| `user_companion` | 用户-伴侣关系（收藏、亲密度），`uk_user_companion (user_id, companion_id)` |
| `note` | **用户笔记（2026-11-16 任务十一）**：`user_id` + `companion_id` + `content` + `tags`（逗号分隔）；索引 `idx_note_user_updated (user_id, updated_at)` 支撑列表查询，`idx_note_companion_deleted (companion_id, deleted)` 覆盖级联删除 |

> 记忆/情绪表（`user_memories` / `user_moods`）**不在 MySQL**，由 Python 服务管理（SQLite `backend/ai_companion.db`），见 3.x。

**迁移脚本**：`schema.sql` 给新库（`CREATE TABLE IF NOT EXISTS`），`migration.sql` 给老库。**执行 migration 必须加 `--force`**——文件开头的旧语句（`ALTER TABLE message ADD COLUMN images`）在已升级的库上会报 1060 并中断后续语句。

预置伴侣：preset-1 小暖 / preset-2 小智 / preset-3 小甜 / preset-4 小酷（dicebear 头像）。

### 2.4 关键接口行为

- **Auth**：`POST /auth/send-email-code`（验证码写 Redis）、`/auth/register`、`/auth/login`、`/auth/refresh`。响应 `AuthResponse{accessToken, refreshToken, tokenType, user{id, email, name, avatar}}`（id 为 String）。**无** `/auth/verify-email-code` 接口。
- **Chat**：`GET /conversations?companionId=&page=&pageSize=` 返回**纯数组**（无 items/total 包装）；`POST /messages` 请求体 `{content: string}`。
- **ChatServiceImpl.sendMessage**：先落库，再调 Python `POST /api/v1/ai/chat`（**非流式**）生成回复并二次落库；Python 失败时返回「抱歉，AI 服务暂时不可用。」。
- **Companion**：CRUD + `PATCH /{id}/favorite`、`PATCH /{id}/intimacy`。
- **Note（2026-11-16 任务十一）**：`NoteController` 提供 4 端点（列表/新增/更新/删除）。归属校验：查不到或不属于当前用户统一抛「笔记不存在」，不区分「不存在」与「无权」；`companionId` 校验伴侣存在（预置伴侣允许）。列表返回**分页对象**（不沿用 `GET /conversations` 的纯数组遗留口径），`pageSize` 上限 100。

- **删除伴侣（`DELETE /companions/{id}`，跨服务级联）**：`CompanionServiceImpl.deleteCompanion` 刻意**不加 `@Transactional`**，跨服务调用放在事务外，只有 MySQL 部分用 `TransactionTemplate` 包住。顺序为先远端、后本地：① `RagClient.listCollectionIdsByCompanion` 调 8002 `GET /api/v1/kb/collections?companionId=...&pageSize=100`；② 逐个 `RagClient.deleteCollection` 调 8002 `DELETE /api/v1/kb/collections/{id}`（8002 自己级联清文档/切片/Chroma）；③ 全成功后本地事务逻辑删 `message` → `conversation` → **`note`**（2026-11-16 任务十一加入）→ `user_companion` → `companion`。8002 任一失败即抛 `ServiceUnavailableException`（HTTP 502），MySQL 一行不动。`RagClient` 用独立 `ragRestTemplate`（连接 2s / 读 3s）fail-fast，不拖死删除链路。
  - ⚠ **路径口径**：8002 所有业务路由前缀是 `/api/v1/kb`（由 `RAG-Knowledge-System/backend/main.py` 的 `include_router(prefix=...)` 注册），且 `pageSize` 上限 **100**（`collections.py` 的 `le=100`）。2026-11-15 曾因写成 `/api/v1/collections?...pageSize=200` 导致删除功能 100% 失败（404 + 422），已修正。

- **AI 头像（`AIServiceImpl`）**：代理 Python 生成，并把 CogView 的第三方临时直链下载落盘到本站 `/uploads/`，返回稳定地址；失败降级 dicebear 并返回 `fallback=true` + `fallbackReason`，不抛异常。使用独立 `avatarRestTemplate`（连接 30s / 读 60s），不与聊天链路共用。详见 `docs/03-API接口文档.md`。

> 已知问题：无（头像假实现已于任务五修复）。

### 2.5 启动

```bash
cd backend-java
mvn spring-boot:run    # 需本地 MySQL + Redis，先执行 schema.sql
```

## 三、Python AI 服务（backend/，:5000）

### 3.1 技术要点

- FastAPI 单应用：路由 + Pydantic 模型集中在 `main.py`
- 统一响应：`{success, message, data, timestamp}`（与 Java 的 code 格式**并存**，前端分别 unwrap）
- 单平台双模型（智谱 GLM，均 OpenAI 兼容协议）：
  - 文本：`glm-4.5-air`（`ZHIPU_API_KEY` / `ZHIPU_BASE_URL` / `ZHIPU_MODEL`）
  - 视觉：`glm-4v-flash`（`ZHIPU_VISION_MODEL`，默认复用 `ZHIPU_API_KEY`）
  - 图像生成：`LLM_IMAGE_MODEL` 置空则头像降级本地 SVG（需要时填 `cogview-3`）
- 文本与视觉共用同一个智谱 key；两者 base URL 均为 `https://open.bigmodel.cn/api/paas/v4`
- 带图请求绕过 LangChain Agent 直接走视觉链路（Agent 的 `HumanMessage` 无法承载 `image_url`）
- 密钥一律经环境变量注入，不硬编码

### 3.2 模块

| 文件 | 职责 |
|------|------|
| main.py | 全部路由：/health、/chat、/chat/stream、/chat/langchain(+stream)、/suggestions、/generate-avatar、/memory、/mood、/metrics |
| llm_client.py | 智谱 GLM 文本 + 视觉双客户端（共用 key） |
| ai_agent.py | LangChain 1.x `create_agent` + 5 工具 |
| rag_service.py | SimpleHashEmbeddings 256 维哈希向量 + Chroma（**待收敛**，见 3.5） |
| avatar_generator.py | 图像生成 + 本地 SVG 降级 |
| memory_service.py | 记忆/情绪 CRUD（示例假数据已于任务四清理，查不到返回空列表）；`update_user_memory` / `delete_user_memory` 带 userId 归属校验，不一致返回 None/False，由端点转 404 |
| preset_responses.py | 预设回复库（降级兜底，**保留**） |

### 3.3 请求/响应模型（camelCase）

- `ChatRequest{systemPrompt, messages[], userMessage, images[], userId}`
- `AvatarRequest{personality, description}` → `data:{avatarUrl}`
- `MemoryCreateRequest{userId, memoryType, keyword, content}`
- `MemoryUpdateRequest{userId, memoryType?, keyword?, content?}` — userId 必填做归属校验，其余 null 不改
- `MoodCreateRequest{userId, mood, score, note}`

**记忆向量双写（2026-11-15 修复）**：POST/PUT/DELETE 三个端点都同步 Chroma，metadata 带 `memory_id`。此前 POST 只写 SQLite，导致编辑/删除的向量同步全空转；现补 `_sync_memory_vector_on_create`，UPDATE 改「先删旧、无条件写新」自愈写法（历史无向量数据编辑一次即补），并修掉 UPDATE 漏传 `memory_type` 一律写 fact 的问题。Chroma 失败只 warning，不影响接口结果（事实源是 SQLite）。

### 3.4 流式协议（SSE）

```
data: {"delta": "增量文本", "done": false}

data: {"delta": "", "done": true}
```

- LangChain 通道为**模拟流式**：全量生成后按块切分下发
- 三层降级链：LangChain agent → OpenAI SDK 直连 → `PRESET_RESPONSES`
- 流式端点需 `X-Service-Token` 共享密钥头（P1-5 已完成）；`SERVICE_TOKEN` 未配置时跳过校验。**仅防误调，非安全加固**（前端 token 会进浏览器产物）

### 3.5 LangChain 工具与 RAG 现状（P1-1 已完成）

工具：`web_search` / `search_user_memory` / `add_user_memory` / `get_mood_history` / `search_knowledge`

- **主入口**：独立 RAG-Knowledge-System（8002），`search_knowledge` 优先 `POST /api/v1/kb/retrieve`（`{companionId, query, topK}`）
- **兜底**：内建 256 维哈希向量 + Chroma，仅在超时/异常/HTTP 5xx 时回落（8002 空 chunks 不回落）
- `companionId` 闭包绑定：有 companionId 时按请求构建 agent，无则复用单例，并发安全
- 工具选择规则：用户本人记忆 → `search_user_memory`；伴侣角色喜好/设定 → `search_knowledge`（2026-11-15 修复偏见）

## 五、服务间调用关系

```
前端(:3000) ── SSE/REST ──▶ Python(:5000) ── search_knowledge ──▶ RAG(:8002)
     │                              ▲                                    │
     └── REST ──▶ Java(:8081) ──────┘ 非流式 REST                        │
                       │                                               │
                       └───────────────────────────────────────────────┘
```

- Java → Python：`ChatServiceImpl` 调 `/api/v1/ai/chat`（非流式）、`AIServiceImpl` 调 `/api/v1/ai/generate-avatar`（任务五）
- Java → RAG（8002）：`RagClient` 在删除伴侣时调 `/api/v1/kb/collections`（列表）与 `/api/v1/kb/collections/{id}`（删除），**注意 `/kb` 前缀**
- 前端 → Java：登录/注册、伴侣、会话消息、图片上传、AI 头像生成、记忆/情绪（任务四起）
- 前端 → Python：SSE 流式聊天（唯一直连业务链路）+ 记忆/情绪读写
