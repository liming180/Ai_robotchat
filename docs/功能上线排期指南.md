## 一、里程碑与依赖关系

```
M0 构建修复 ──▶ M1 API 层基建 ──▶ M2 鉴权打通 ──▶ M3 业务打通 ──▶ M4 流式落库
                                                                        │
                              M5 数据真实化（RAG 收敛/清假数据） ◀────────┘
                                          │
                                          ▼
                                    M6 清理与上线
```

- **M0 是硬前置**：当前 `npm run build` 失败，任何前端发布都不可能
- **M1 是 M2/M3/M4 的共同前置**：没有统一 API 层，逐处改 fetch 会重复返工
- **M4 依赖 M2**：落库需要登录态 userId
- **M5 可与 M3/M4 并行**（不同人/不同服务），但需在 M6 前合流
