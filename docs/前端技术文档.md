## 三、当前网络调用（关键事实）

**前端从未调用 Java 8080。** 业务数据全部来自 Pinia + localStorage mock。

仅两处直连 Python 5000：

| 位置 | 端点 | 用途 |
|------|------|------|
| `composables/useStreamingChat.ts` | `POST /api/v1/ai/chat/stream` 或 `/chat/langchain/stream`（enableRAG 切换） | SSE 流式聊天 |
| `pages/CreatePage.vue` | `POST /api/v1/ai/generate-avatar` | 伴侣头像生成 |

已知问题（对应收敛清单 P0）：

1. `useStreamingChat.ts#L31` 写死 `userId: 'default_user'`
2. `http://localhost:5000` 硬编码 **2 处**（`useStreamingChat.ts:3` 的 `API_BASE` 常量、`CreatePage.vue:265`），无 `.env`
3. `ChatInput.vue` 引用不存在的 `chatStore.sendMessage()`，`npm run build` 失败（TS2339）

## 四、SSE 流式聊天（useStreamingChat）

- 协议：`fetch` POST + 逐行解析 `data: {...}`（非 EventSource，因需传 body）
- 帧格式：`{"delta": "增量文本", "done": false}`；结束帧 `{"delta": "", "done": true}`
- 三层降级由后端负责（LangChain → SDK 直连 → 预设库），前端只消费 delta
- LangChain 通道为**模拟流式**（全量生成后切块），前端感知为块状到达

```ts
// 现状核心片段（简化）
const API_BASE = 'http://localhost:5000'  // P0-4 待抽到 .env
const payload = { userMessage, userId: 'default_user', messages, images }  // P0-3 待改
```
