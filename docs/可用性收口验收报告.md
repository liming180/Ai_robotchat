## 三、compose restart 策略

- **前置更正**：用户任务描述中的 etcd / minio 是独立容器，实际 `deploy/milvus/docker-compose.yml` **只有 `standalone` + `tei`**：Milvus 用 `ETCD_USE_EMBED=true` 内嵌 etcd、`COMMON_STORAGETYPE=local` 本地存储，无独立 etcd/minio 进程。故只给 `standalone` 补策略（tei 原本已是 `unless-stopped`）。
- 改动：`restart: unless-stopped`（不用 `always`，保证 stop-all 的 `compose stop` 是手动停止语义、不被反拉起）。
- 生效：`docker inspect` → `restart=unless-stopped`。
- **验收口径**：`restart` 策略**不覆盖 `docker stop`**（Docker 设计：手动停止被尊重）。验证崩溃自愈必须用 `docker exec milvus-standalone kill 1` 模拟非手动退出。

## 四、8002 `/health` 探活 Milvus

### 改动
- 新增 `app/core/health.py::probe_milvus()`：
  - 每次新建 `MilvusClient(uri, user, pwd, timeout=MILVUS_HEALTH_TIMEOUT)` → `get_server_version()` → `finally: close()`；
  - **不复用检索连接**（隔离 25s 检索超时），默认 2.0s；1s 结果缓存（防 start-all 每秒轮询把 Milvus 打爆）；
  - 探活窗口内临时把 `pymilvus*` logger 调到 CRITICAL，避免失败 traceback 刷屏；
  - 失败只写一行状态翻转日志，异常绝不外抛。
- `main.py::health` 由 `async def` 改 **普通 `def`**（pymilvus 同步阻塞，走线程池；与 `/retrieve` 同口径）。
- Milvus 不可用 → **HTTP 503** + 统一 `fail()` 结构（code=`MILVUS_UNAVAILABLE`）；chroma 后端或开关关闭 → `disabled` 且 200。
- 配置：`MILVUS_HEALTH_ENABLED=true`、`MILVUS_HEALTH_TIMEOUT=2.0`（`.env.example` + `config.py`）。
- 测试：`tests/test_health_milvus.py` 7 项（sync def / 200 / 503 / disabled / chroma / 开关 / 异常吞掉）。

### 实测
- 健康：`{"milvus":"connected","milvusLatencyMs":77,"milvusVersion":"2.6.0"}`，延迟 1~77ms。
- 停机：503，`error.code=MILVUS_UNAVAILABLE`，一次探活约 1.5~2.1s。
- 全量测试：`pytest tests/` **33 passed**。
